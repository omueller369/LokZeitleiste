# LokZeitleiste 0.25 RC1

Vorabversion des Webportals und Backends für Tests, Stand 30.10.2026. Grundlage: `setup/debian-testumgebung` (02c8661) mit den Änderungen aus PR #2 (2c40782). Die Android-Portal-App selbst erhält mit diesem Paket keine neue APK; sie verwendet die aktualisierte Serveroberfläche nach dem Neuladen.

## Enthalten

- Vorhandene Ortssuche im 5-km-Umkreis, Abgleich mit der bestehenden DS100-Datenbank, Karte und Checkbox-Übernahme bleiben erhalten.
- Nach mehr als fünf Minuten zusammenhängendem Stillstand unter 3 km/h: Ortsabfrage, wenn kein automatischer Standort gefunden wurde.
- Dropdown-Suche über Ortsname oder DS100; alternativ einen freien Ortsnamen ohne Kürzel übernehmen.
- Einmalige Rückfrage je Aufenthalt; „Später“ verändert keine Standortangaben. Die Aufzeichnung läuft weiter, bei Weiterfahrt schließt die Abfrage.
- Standortwahl bleibt beim lokalen Speichern, GPS-Abgleich, Import und Speichern der Zugfahrtdetails erhalten. Die aufgezeichnete Punktfolge wird nicht verändert. Keine Datenbankmigration.

## Prüfstand und bekannte Grenzen

- Vollständiger Python-Testbestand vor der Versionskennzeichnung: 333 Tests erfolgreich.
- 37 JavaScript-Testdateien erfolgreich, einschließlich GPS im Browser, Android-Anbindung, Live-Abfrage und Import. Ein vorhandener Tabellen-Test (`report-table-time.test.cjs`) scheitert mit demselben veralteten Spaltenindex auch auf dem unveränderten Testbranch. Dieser bekannte Fehler ist kein Ergebnis der RC-Änderungen.
- Die Release-Pipeline prüft die betroffenen GPS- und Zugfahrtfunktionen erneut vor Veröffentlichung und erzeugt SHA-256-Prüfsummen.
- Ein Gerätetest mit echtem GPS steht aus. Dies ist ein Release Candidate, keine stabile Produktionsfreigabe.
- Das vorhandene DS100-Verzeichnis wird unverändert verwendet; Datenstand und Pflegehinweise stehen in `backend/lokzeitleiste/accounts/STATION_SOURCES.md`.

## Update des eigenständigen CTL-Testservers

Nur für eine bereits mit `install-ctlsoftware-test.sh` eingerichtete Installation. Das Archiv enthält Quellcode und Installer, keine Datenbank oder persönlichen Unterlagen. Für Docker oder ISPConfig gelten die jeweiligen Update-Anleitungen.

Auf dem Testserver per SSH:

```bash
curl -fL https://github.com/omueller369/LokZeitleiste/releases/download/v0.25-rc.1/LokZeitleiste-v0.25-rc.1.tar.gz -o /tmp/LokZeitleiste-v0.25-rc.1.tar.gz
sudo tar -xzf /tmp/LokZeitleiste-v0.25-rc.1.tar.gz -C /opt
sudo bash /opt/LokZeitleiste-v0.25-rc.1/install-ctlsoftware-test.sh --update --source /opt/LokZeitleiste-v0.25-rc.1
```

`--source` ist erforderlich: Ohne diese Angabe würde der Installer den normalen Testbranch statt dieser festen RC-Version verwenden. Die Update-Routine sichert Datenbank, Konfiguration und den bisherigen Backend-Code unter `/etc/ctlsoftware-test-setup/backups/`. Bestehende Arbeitsberichte, Bilder und Postfachnachrichten werden erhalten. Sicherung bei einem Fehler aufbewahren; es gibt keinen automatischen Restore.

Nach erfolgreichem Update das Portal neu laden. In der Softwareinformation muss `0.25-rc.1` stehen. Die Veröffentlichung allein installiert nichts auf dem Server und führt PR #2 nicht zusammen.
